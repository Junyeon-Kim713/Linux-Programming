# 리눅스 명령어란? 또, 실제 리눅스 명령어의 정체는 무엇인가?
- 명령어란 운영체제에 작업을 지시하 단어이다. 실제로는 실행파일 명이다.
# 리눅스에서 많이 사용되는 명령어 10개
| 명령어 | 주요 기능 | 대표 활용 예시 |
| :--- | :--- | :--- |
| **`ls`** | 디렉토리 파일/폴더 목록 출력 | `ls -la` (상세 정보 및 숨김 파일 전체 표시) |
| **`cd`** | 작업 디렉토리 이동 | `cd ~` (홈 디렉토리 이동), `cd ..` (상위 이동) |
| **`pwd`** | 현재 작업 경로 출력 | `pwd` (현재 위치의 절대 경로 확인) |
| **`mkdir`** | 새 디렉토리(폴더) 생성 | `mkdir -p path/to/folder` (하위 디렉토리까지 한번에 생성) |
| **`rm`** | 파일 및 디렉토리 삭제 | `rm file.txt`, `rm -rf folder` (디렉토리 강제 삭제) |
| **`cp`** | 파일 및 디렉토리 복사 | `cp file.txt backup.txt`, `cp -r dir1 dir2` (디렉토리 복사) |
| **`mv`** | 파일 이동 및 이름 변경 | `mv old.txt new.txt` (이름 변경), `mv file.txt /tmp/` (이동) |
| **`cat`** | 파일 내용 화면 출력 및 연결 | `cat config.txt` (파일 내용 전체 보기) |
| **`grep`** | 특정 문자열/패턴 검색 | `grep "error" log.txt`, `ps aux \| grep python` |
| **`sudo`** | 최고 관리자(root) 권한 실행 | `sudo apt update`, `sudo vim /etc/hosts` |
# 커널과 셸
- 커널은 CPU나 메모리 같은 하드웨어를 관리하면 명령어를 실행하고 프로세스를 관리하는 운영체제의 핵심 부분
- 셸은 사용자와 커널 사이에서 명령어를 받아들이고 커널의 실행 결과를 출력하는 소프트웨어
# 프롬프트 문자열에서 문자 ~의 의미는?
- 현재 로그인한 사용자의 홈 디렉토리를 의미한다.
# 셸 종류 및 비교: sh, bash, zsh

---

## 1. 한눈에 보는 요약 비교표

| 구분 | **sh (Bourne Shell)** | **bash (Bourne Again Shell)** | **zsh (Z Shell)** |
| :--- | :--- | :--- | :--- |
| **개발 연도** | 1979년 | 1989년 | 1990년 |
| **개발자 / 프로젝트** | Stephen Bourne | Brian Fox (GNU 프로젝트) | Paul Falstad |
| **주요 적용 시스템** | 초기 유닉스, 임베디드, 부팅 스크립트 | 대부분의 리눅스 배포판 (Ubuntu, CentOS 등) | macOS (Catalina 이후 기본), 사용자 커스텀 |
| **주요 목적** | 가벼움, 높은 이식성, 기본 동작 | 표준화된 기능, 셸 스크립팅, 호환성 | 높은 생산성, 대화형(Interactive) 사용 편의성 |
| **자동 완성** | 미지원 | 기본 지원 (`Tab` 키) | 강력함 (대소문자 무시, 경로 자동 교정 등) |
| **플러그인 / 테마** | 미지원 | 제한적 지원 | 매우 뛰어남 (Oh My Zsh, Powerlevel10k 등) |
| **리소스 소비** | 극히 적음 | 적음 | 상대적으로 보통 |

---

## 2. 각 셸별 상세 특징

### 1) sh (Bourne Shell)
* **설명**: 모든 유닉스 계열 셸의 조상 격으로, 표준 유닉스 환경의 기본 인터페이스였습니다.
* **장점**:
  * 실행 속도가 매우 빠르고 메모리 점유율이 최소화되어 있습니다.
  * 시스템 초기화 스크립트나 용량 제약이 심한 임베디드 리눅스 시스템에 적합합니다.
* **단점**:
  * 방향키를 이용한 과거 명령어 호출, 자동 완성, 커서 이동 등 현대적인 대화형 편의 기능이 없습니다.

---

### 2) bash (Bourne Again Shell)
* **설명**: GNU 프로젝트의 일환으로 sh의 기능을 크게 확장하여 제작된 오픈소스 셸입니다.
* **장점**:
  * 대부분의 리눅스 배포판에서 기본 셸로 사용되므로 호환성이 가장 뛰어납니다.
  * 명령어 히스토리 관리, 백그라운드 작업 제어, 표준화된 셸 스크립팅 지원이 강력합니다.
* **단점**:
  * 기본 설정 상태에서의 시각적 테마나 대화형 기능이 zsh에 비하면 단순합니다.

---

### 3) zsh (Z Shell)
* **설명**: bash, ksh, tcsh 등의 장점을 흡수하고 사용자 편의 기능을 대폭 추가한 현대적 셸입니다.
* **장점**:
  * **스마트 자동 완성**: `cd /u/l/b` 입력 후 `Tab` 입력 시 `/usr/local/bin`으로 자동 변환.
  * **프레임워크 확장성**: `Oh My Zsh`를 활용한 테마 변경, Git 브랜치 상태 표시, 명령어 하이라이팅, 오탈자 자동 교정.
  * macOS 기본 셸 채택으로 대중적 보급율 증가.
* **단점**:
  * 플러그인을 과도하게 설치할 경우 초기 로딩 속도가 미세하게 느려질 수 있습니다.

---
# 셸 스크립트란?
- 리눅스/유닉스 환경의 셸(Bash, zsh, sh 등)에서 실행할 수 있는 명령어들을 하나의 파일로 묶어서 순차적으로 자동 실행하도록 작성한 프로그램
## 사용하는 이유
* 작업 자동화: 매일 수행하는 서버 백업, 로그 정기 삭제, 시스템 점검 등을 자동화할 수 있습니다.
* 시간 절약 및 실수 방지: 긴 명령어를 일일이 타이핑할 필요가 없어 작업 속도가 빠르고 인적 오류를 줄입니다.
* 높은 이식성: 별도의 컴파일 과정이 필요 없는 해석형(Interpreted) 언어로, 리눅스 환경이라면 어디서나 실행 가능합니다.
# Windows에서 사용하는 CLI방식의 셸의 종류
| 셸 이름 | 핵심 데이터 방식 | 주 용도 및 스크립트 | 주요 특징 |
| :--- | :--- | :--- | :--- |
| **Command Prompt**<br>(`cmd.exe`) | 텍스트 스트림 | • 단순 명령어 실행<br>• `.bat`, `.cmd` 스크립트 | MS-DOS 기반의 전통 셸이며, 하위 호환성을 위해 유지됨 |
| **PowerShell**<br>(`powershell.exe` / `pwsh`) | **.NET 객체 (Object)** | • 시스템 자동화 및 관리<br>• `.ps1` 스크립트 | `동사-명사` 형태의 Cmdlet 구조를 가지며, 데이터를 객체 단위로 전달 |
